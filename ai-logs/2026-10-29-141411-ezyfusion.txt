  Step 1 (lib/billing.ts): these are the parts you'll be asked about in the
  walkthrough.
  - Dates are never Date objects. A date string becomes a plain day count since
    1970 using a pure calendar formula, so the server's timezone can't change
    any result. I avoided Date.UTC because it silently turns years below 100
    into 19xx.
  - "Today in Malaysia" is floor((epoch ms + 8h) / 1 day). Malaysia has no
    daylight saving, so a fixed +8 hours is exact.
  - Anchors always count from the start date: Jan 31 gives Feb 28, then Mar 31,
    never Mar 28.
  - Proration uses exact integer maths, so half-sen cases round up: Ben's last
    period is 100029 × 15/30 = 50014.5, which becomes 50015 (tested).
  - Ringgit parsing is one strict pattern plus integer maths; it never parses a
    float.

  Decisions you should know about:
  - Zero-sen invoices are possible. A 1-sen rent prorated over 1 of 31 days
    rounds to 0, and the function returns that as a valid invoice. The database
    will allow amount_sen >= 0, not > 0, so creating such a lease doesn't crash.
  - Allocation logic lives in billing.ts too. The allocation order and the "fill
    each invoice, keep the remainder as unapplied" logic are pure functions
    here, so they're unit-tested (one of the bonus items). The database code
